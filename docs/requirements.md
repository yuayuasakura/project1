# プロジェクト概要
グッズ管理
自分が持っているグッズを一覧として見ることができる

# ユーザーストーリー(10個以上)
1. グッズを買ったファンとして、買ったグッズを記録したい。なぜなら、どのグッズを持っているのかすぐわかるようにしたいから。
2. 同じグッズを複数持つファンとして、持っている数を登録したい。なぜなら、自分がいくつ持っているのかをすぐ知りたいから。
3. このシステムを初めて使う人として、新しいアカウントを作りたい。なぜなら、自分のグッズ情報を自分だけのものとして保存したいから。
4. アカウントを持っている人として、アカウントにログインしたい。なぜなら、自分のグッズ一覧を見たいから。
5. このグループのファンとして、メンバー一覧からメンバーを選びたい。なぜなら、名前の入力の手間を省きたいから。
6. グッズを登録するファンとして、一つでいいか、集めるかを設定したい。なぜなら、二重買いを防ぎたいグッズと、数を増やしたいグッズを分けて管理したいから。
7. たくさん集めているファンとして、+/-ボタンで所持数を変更したい。なぜなら、簡単に数を記録したいから。
8. 登録内容を間違えたファンとして、グッズ情報を編集したい。なぜなら、正しい情報で管理したいから。
9. お店にいるファンとして、持っていないものだけ表示したい。なぜなら、今持っていないものだけを知りたいから。
10. お店にいるファンとして、グッズ名で検索したい。なぜなら、すでに持っているかその場で確認したいから。
11. お店にいるファンとして、種類で絞り込みしたい。なぜなら、目の前の商品と同じ種類のグッズだけを見比べたいから。

# 機能要件一覧(必須の機能がわかるように)
＜会員登録・認証＞(Must have)
・メールアドレスでユーザー登録できる
・ログイン/ログアウトできる
・パスワードのリセットができる
・ログインしていないとグッズ情報を閲覧できない
＜グッズ登録＞
・買ったグッズを記録できる(Must have)
・一つでいいか、集めるか、を設定できる(Must have)
＜所持数管理＞
・グッズの所持数を記録できる(Must have)
・+/-ボタンで所持数を1ずつ変更できる(Should have)
・所持数は0未満にならない(Must have)
＜グッズの閲覧・検索＞
・自分が持っているグッズを一覧で表示できる(Must have)
・自分が持っていないグッズを一覧で表示できる(Must have)
・グッズの詳細を閲覧できる(Should have)
・グッズ名で検索することができる(Must have)
・メンバーで絞り込みができる(Could have)
・種類で絞り込みができる(Could have)
・一覧で一つだけか集めるかを区別して表示する(Must have)
・回収柄一覧(Must have)

# 非機能要件
＜パフォーマンス＞
・ページ読み込み時間：3秒以内
・検索・絞り込み結果の表示：2秒以内
・同時接続者数：100ユーザー
＜セキュリティ＞
・通信はHTTPS化
・パスワードはハッシュ化して保存
・パスワードは8文字以上、英字と数字を含む
・ログインしたユーザー本人のグッズ情報のみ閲覧・編集できる
・XSS、CSRF、SQLインジェクション対策を実施
＜可用性＞
・稼働率：99%以上
・定期メンテナンス：月1回、深夜
・データのバックアップ：1日1回
＜互換性＞
・対応ブラウザ：Chrome、Safari、Edge最新版
・スマホでの利用を優先したレスポンシブ対応(スマホ、タブレット、PC)
・対応OS：iOS、Android最新版
＜使いやすさ＞
・ボタンはスマホで片手で押せる大きさにする
・検索欄はグッズ一覧画面の上部に常に表示する
・捜査に失敗した時はエラーの内容がわかるメッセージを表示する
＜保守性＞
・ドキュメント整備
。コーディング規約準拠
・テストコード作成
